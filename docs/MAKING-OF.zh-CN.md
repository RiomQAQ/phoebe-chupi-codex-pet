# 宠物制作流程

[English](MAKING-OF.md) · **简体中文** · [文档目录](README.zh-CN.md)

这份指南以菲比啾比为例，介绍如何确定角色、规划连贯动作、逐帧制作，再检查最终安装包。

项目使用 **GPT-6-Astra** 与内置图像生成功能制作。脚本负责图片归一化、预览、校验和打包。

## 1. 确定造型参考

先用正面、侧面、背面参考确定轮廓，再开始画动作。本项目主要采用署名为蓝蓝铜离子的社区三视图。官方菲比资料用于确认身份与配色，社区图和动作研究用于把握 Q 版造型。

![社区三视图](../art/canonical/user-reference.png)

记录每份参考的来源、作者署名和用途。合集发布者不一定是原作者。[参考来源](SOURCES.zh-CN.md)分别列出了角色资料、社区造型和动作研究。

## 2. 建立两张姿势基准

坐姿基准使用打开的电脑，移动基准抱着同一台合上的电脑。标准动作围绕这两种姿势展开。

| 坐姿基准 | 抱电脑基准 |
| :---: | :---: |
| ![坐姿角色](../art/canonical/seated-master-approved.png) | ![抱着电脑移动](../art/canonical/carry-master-approved.png) |

每帧都要保持以下特征：

| 特征 | 基准 |
| --- | --- |
| 轮廓 | 宽白帽沿、深紫帽带、浅金长发、紧凑的身体。 |
| 面部 | 小圆脸、分层紫色眼睛、稳定的眉距和下巴。 |
| 配饰 | 蓝色发夹在观看者右侧，呆毛和蓝布在左侧。 |
| 服装 | 白色衣服、深色手套、金色装饰、条纹腿部和深色鞋。 |
| 电脑 | 一层屏盖、一处铰链、一套键盘，双手位置合理。 |
| 线条 | 深色外轮廓、金棕色内部发丝线、克制的平涂配色。 |

先确认基准图，再扩展整套动作。角色造型始终以基准图为准，相邻帧只用于判断动作幅度。

## 3. 规划完整动作

从应用要求的[九类动作行](FORMAT.zh-CN.md#动作行)出发，安排同一套日常行为：工作、停下来等回复、检查结果、打招呼和求助。移动时抱合上的电脑，坐姿小跳时仍带着打开的电脑。

为每个循环确定起始姿势、主要动作和结束姿势。先统一坐姿基线，再增加表情变化。当前版本的眨眼包含半闭眼和闭眼；一直睁眼的方案作为未采用的试验保存在档案中。

## 4. 逐帧生成与修改

每一帧按以下顺序制作：

1. 附上对应的姿势基准，以及已认可的相邻帧。
2. 写清状态、帧位置、动作目标和需要保持的特征。
3. 生成一张透明背景的独立角色图。
4. 同时检查原尺寸图片和原生尺寸预览。
5. 带着同一张基准图，修复可定位的问题。
6. 对比前后帧，以及使用同类姿势的其他状态。

[提示词示例](PROMPTS.zh-CN.md)提供了可用模板。候选图和采用图分开保存，避免让失败稿变成下一帧的参考。

| 常见问题 | 修改方向 |
| --- | --- |
| 多出手套、手臂或袖子 | 数清双手，修复手臂与袖子的连接。 |
| 重复眉毛或面部杂线 | 按基准图恢复面部位置关系。 |
| 两层电脑屏盖或键盘 | 恢复一处铰链、一层屏盖和一套键盘。 |
| 头、帽子或下巴改变大小 | 对照基准图修比例。 |
| 配饰换边 | 分别画左右姿态，保留不对称特征。 |
| 文件名正确，画面却看向反方向 | 藏起标签审查后，修改头部和眼神的方向依据。 |

局部修改可能影响别处。每次修复后，仍要重新查看完整画面。

## 5. 制作 Dot 转头姿态

先画上 `000`、右 `090`、下 `180`、左 `270`。不看标签也能辨认后，再按 22.5° 补齐中间方向。最终得到 16 个离散姿态，由鼠标方向选择。

坐姿身体、电脑、双脚和相机位置保持稳定。用头部朝向、眼神和帽顶的可见面积表达方向，不把它画成全身转面图。

![十六个转头方向](../previews/directions.png)

审查顺时针循环、`337.5 → 000` 的首尾衔接，以及无标签的水平和垂直对比。[方向审查](REVIEW.zh-CN.md#方向审查)介绍了具体方法。

把固定的电脑当参照，观察脸颊宽度、眼距、眼睛大小和眼睛到下巴的距离。它们应随转头逐渐变化。每张中间帧都与前后两帧比较，也要看注视姿态回到待机的过程，这时更容易发现脸被拉长的问题。

如果窄侧脸下一帧突然展开成大正脸，从一张比例正确的端点出发，重新画完整中间帧。头、脸、刘海和附着的配饰要一起转动。方向能够辨认，脸仍可能忽大忽小，因此方向与动作连贯性需要分别审查。

v1.0.2 使用图像生成功能重画了 12 张完整转头帧，另有 4 张沿用原画：`022.5`、`045`、`067.5` 和 `090`。最新一轮脸部细化覆盖 `000`、`157.5`、`247.5`、`292.5`、`315`、`337.5`，处理脸颊过窄，以及从左上注视姿态转回时脸部显得变大的问题。帽子设计保持一致，没有粘贴脸部或对脸部做局部变形。

## 6. 归一化与拼图

保留高分辨率原图。对采用帧使用统一取景和缩放，再放进 **192 × 208** 的格子。不要按每张图自己的可见边界单独撑满。

在浅、深背景下检查透明度与轮廓颜色。原生透明边缘已经干净时，直接保留，避免把附近填色混进深色描线。[v1.0.1 修复记录](OUTLINE-REPAIR.zh-CN.md)说明了这类问题。

拼成 **1536 × 2288** 的整图，保留 73 个有效格和 15 个全透明格。导出无损 WebP，与认可的 PNG 比对像素，再从这份 WebP 生成最终裁剪帧和预览。

v1.0.2 的 57 张标准动作帧（含眨眼）保留了 v1.0.1 的原始 RGBA 像素。前九行与固定基准比对，保护这些动作及其中的空格，最后两行转头图则允许更新。

## 7. 审查完整动作

按原生尺寸和预期播放速度看每个循环。检查首尾衔接、各姿态中的电脑，以及小跳是否落回坐姿基线。转头循环在两种背景下都要看。

结合[画面检查与当前结果](REVIEW.zh-CN.md)完成验收。尺寸正确不能证明画面正确；如果 PNG 和 WebP 都已经包含同一种颜色错误，两者一致也发现不了问题。

v1.0.2 由 3 名审查者分别重新完成独立方向审查，14 组严格多数判定均通过。脸部大小的修复还通过原生 192 × 208 浏览器逐帧检查和播放截图抽查。`045` 与 `067.5` 仍然接近，`225 → 247.5` 和 `270 → 292.5` 仍有较大的姿态跳变。当前修订尚未在原生 Dot 中检查，之前的桌面端和 Dot 检查对应 v1.0.1。[转头修复检查记录](look-repair-qa/README.zh-CN.md)保存了这次范围。

## 8. 校验与打包

在仓库目录中使用 Python 3.10+：

```sh
python3 -m pip install -r requirements.txt
python3 scripts/render_previews.py
python3 scripts/validate.py --report docs/validation.json
python3 -m unittest discover -s tests
python3 scripts/package.py
```

打包脚本在 `dist/` 下生成双文件安装 ZIP、完整图片档案 ZIP 和 `SHA256SUMS.txt`。需要 MP4 预览时运行 `python3 scripts/render_previews.py --mp4`，并准备 FFmpeg。

有意修改图片时，发布前需要经过审查的 PNG 基准与校验值。v1.0.2 使用 [art/approved/v1.0.2/spritesheet.png](../art/approved/v1.0.2/spritesheet.png)，其来源记录和固定的标准动作行参考写在 [art/approved-runtime.json](../art/approved-runtime.json) 中。保留历史基准和回归用例，保持版本标签与 `VERSION` 一致，并核对署名。发布后下载公开文件，与本地通过校验的文件比对。
