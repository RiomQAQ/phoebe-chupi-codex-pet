# 审查与校验

[English](REVIEW.md) · **简体中文** · [文档目录](README.zh-CN.md)

画面、动作和发布文件分别检查。造型以基准姿势为准，发布验收以最终 WebP 为准。

## 逐帧检查

每个有效格都在浅色和深色背景下看一遍。先按原生 **192 × 208** 尺寸检查，定位问题时再放大局部。

| 检查项 | 通过标准 |
| --- | --- |
| 角色一致性 | 脸、帽子、头发、服装和头身比例符合基准。 |
| 配饰 | 发夹在观看者右侧，呆毛和蓝布在左侧。 |
| 肢体 | 只有预期的两只手和手臂，手套与袖口连接清楚。 |
| 面部 | 紫色眼睛、眉毛、下巴和嘴保持一致，没有重复杂线。 |
| 电脑 | 一层屏盖、一处铰链、一套键盘，双手接触位置合理。 |
| 轮廓 | 深色外线连续，金棕色内部发丝线保留原色。 |
| 透明度 | 没有不透明底色、轮廓裁切、杂色边或内部透明洞。 |
| 位置 | 应当静止的身体、电脑和地面接触点保持稳定。 |

改动帧要对比基准图、前后帧，以及相同姿势的其他状态。归一化和编码后重新检查。

## 检查完整动作

- 按预期速度播放九类动作，检查每个循环的首尾衔接。
- 查看 `idle → jumping → idle` 的起跳、电脑跟随和落地归位。
- 把工作、等待、检查和求助的表情连起来看，确认是同一个角色。
- 对比两个移动方向的比例和配饰位置。
- 播放 16 个转头方向及首尾循环，分别观察身体、电脑的漂移与头部动作。

可使用[全部动作](../previews/all-states.gif)、[小跳衔接](../previews/idle-jump-idle.gif)、[转头循环](../previews/look-loop.gif)和[深色预览](../previews/dark)。GIF 的颜色较少；[PNG](../art/final/spritesheet.png) 与[原像素裁剪帧](../art/frames)保留发布图片的完整像素。

## 方向审查

先看带标签的方向总览和顺序循环，再用无标签 A/B 图片判断实际朝向：

1. 比较 7 组水平、7 组垂直方向，四个正方向必须清楚。
2. 隐藏标签和答案，打乱 A/B 顺序。
3. 由 3 名独立审查者说明画面看向的屏幕方向及依据，允许回答不确定。
4. 揭晓答案前保存判断，再按每张图的严格多数汇总。
5. 有分歧时回到连续动作中核对，再决定保留或修复。

v1.0.2 由 3 名审查者分别重新完成独立 A/B 审查，14 组严格多数判定均通过。独立答案、答案表和校验见[转头修复检查记录](look-repair-qa/README.zh-CN.md)。v1.0.1 的答案继续保存在[历史检查记录](repair-qa/README.zh-CN.md)中。

最新一轮脸部细化覆盖 `000`、`157.5`、`247.5`、`292.5`、`315`、`337.5`，处理脸颊过窄，以及从左上注视姿态转回时脸部显得变大的问题。每张都由图像工具生成完整帧，没有粘贴脸部或对脸部做局部变形。

动作测量采用 alpha > 16 的可见边界。[validation.json](validation.json) 的原始边界包含所有非零透明像素，两种测量方式不要混用。位置和像素差异数据用于定位需要检查的切换，单靠这些数字不能证明脸部一致或动作流畅。

当前浏览器检查在 1× 尺寸下正向、反向逐帧查看了 `270 → 292.5 → 315 → 337.5 → 000`，并用 2× 视图辅助定位。自动播放通过连续几张截图抽查，因此不是连续视频审查。早期候选中明显的整张脸变大，在原生尺寸下已不再明显；姿态跳变仍然可见。v1.0.1 已在 macOS 桌面端和 Dot 中检查。当前修订尚未安装到原生 Dot 中检查，Windows 画面也尚未实测。

## 已知限制

- `045` 与 `067.5` 看起来接近。
- `225 → 247.5` 和 `270 → 292.5` 比相邻姿态的变化更明显。后者有可见的抬头跳变，`292.5 → 315` 中较远一只眼睛的张开也较明显。
- Dot 从 16 张离散画面中选择，转头会呈现可见的角度步进。
- 眨眼包含半闭眼和闭眼，减少动态效果或应用时序可能使某个姿态停留。
- v1.0.2 的原生 Dot 检查和 Windows 画面检查仍待完成。早期方向反馈保存在[已关闭的 Issue #2](https://github.com/RiomQAQ/phoebe-chupi-codex-pet/issues/2)。

[描线修复记录](OUTLINE-REPAIR.zh-CN.md)说明了 v1.0.0 的清理错误与 v1.0.1 的修正：恢复 88,948 个可见像素的 RGB，并核对 263,885 个深色描线像素无差异。这些是历史修复数据，不是 v1.0.2 新画图片的像素数量。v1.0.1 快照保存在 [art/releases/v1.0.1](../art/releases/v1.0.1)。导出检查仍要吸取这个教训：如果两种格式都已有同一个错误，仅比对两者无法发现。

## 运行文件校验

安装仓库依赖后，使用 Python 3.10+：

```sh
python3 scripts/validate.py --report docs/validation.json
python3 -m unittest discover -s tests
```

校验器检查五字段清单、静态 v2 图片、格子数量与边距、PNG/WebP 一致性、最终裁剪帧、认可原图一致性、档案哈希、解码、元数据、常见隐私标记、文件大小和发布校验值。回归测试继续覆盖有问题的 v1.0.0 整图和已确认的头发像素，也检查认可发布图片与固定的标准动作行。

当前像素检查读取 [art/approved-runtime.json](../art/approved-runtime.json)，核对 [art/approved/v1.0.2/spritesheet.png](../art/approved/v1.0.2/spritesheet.png) 的校验值，再将完整 RGBA 像素与发布文件比对。另有独立检查把前九行固定到 v1.0.1 PNG，保护全部 57 张标准动作帧，以及这些行中的全透明格。有意修改图片时，需要经过审查的新基准和校验值，同时保留历史原图与回归用例。CI 运行文件校验和回归测试，画面审查仍需单独完成。
