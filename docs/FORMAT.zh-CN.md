# 精灵图格式规范（v2 Atlas Specification）

[English](FORMAT.md) · **简体中文** · [返回文档目录](README.zh-CN.md)

菲比啾比采用 Codex **v2 静态透明精灵整图（Sprite Atlas）** 格式。注意 `spritesheet.webp` 本身是一张**单帧无损透明静态大图**，而不是动图；Codex 客户端在运行时按当前任务状态或鼠标角度，实时裁剪对应的格子播放动画。

---

## 安装结构与五字段清单

一个可移植的 v2 本地宠物包只包含两个文件，不包含任何账号 ID 或机器私有路径：

```text
phoebe-chupi/
├── pet.json           # 5 字段标准清单（UTF-8 JSON）
└── spritesheet.webp   # 1536 × 2288 无损 RGBA WebP 整图
```

`pets/phoebe-chupi/pet.json` 的完整内容如下：

```json
{
  "id": "phoebe-chupi",
  "displayName": "Phoebe Chupi · Coding Companion",
  "description": "Phoebe Chupi, seated with her laptop. For Codex pets and Dot, with blinking, small hops, and a head that follows your cursor. 菲比啾比·坐好了（眨眼版）。",
  "spriteVersionNumber": 2,
  "spritesheetPath": "spritesheet.webp"
}
```

| 字段名 | 类型与取值 | 作用说明 |
| --- | --- | --- |
| `id` | `"phoebe-chupi"` | 本地宠物包的唯一标识符，通常与文件夹名保持一致。 |
| `displayName` | 字符串 | 在 Codex 设置列表与悬浮提示中展示的名称。 |
| `description` | 字符串 | 宠物简介（中英双语描述特征与能力）。 |
| `spriteVersionNumber` | `2`（整数） | 声明采用 8 列 × 11 行（含末尾两行 Dot 16 向转头）的 v2 网格规范。 |
| `spritesheetPath` | `"spritesheet.webp"` | 相对于 `pet.json` 所在目录的整图文件名。 |

原生导入脚本 `scripts/install.py` 会从仓库根目录的 `VERSION` 读取发布标签，拼出对应的官方导入 URI（参数说明见 [安装指南 · 原生导入](INSTALL.zh-CN.md#原生导入)）。

## 格子布局与可视化网格图例

| 属性项目 | 规格数值 | 技术说明 |
| --- | --- | --- |
| **编码格式** | 无损 WebP（含 8-bit Alpha） | 解码后的 RGBA 像素与 `art/final/spritesheet.png` 逐字节完全一致。 |
| **整图分辨率** | **1536 × 2288 px** | 宽 `8 × 192 = 1536`，高 `11 × 208 = 2288`。 |
| **网格行列** | **8 列 × 11 行**（共 88 格） | 行号 `r ∈ [0, 10]`，列号 `c ∈ [0, 7]`，从左上角 `(0, 0)` 开始编号。 |
| **单格尺寸** | **192 × 208 px** | 第 `(r, c)` 格的精确像素矩形为 `(192c, 208r, 192(c+1), 208(r+1))`。 |
| **有效格数量** | **73 格** | 前 9 行共 **57 张标准动作帧** + 第 9、10 行共 **16 张 Dot 转头姿态**。 |
| **全透明留空** | **15 格** | 不足 8 帧的动作行右侧剩余格子必须保持 `RGBA = (0, 0, 0, 0)` 全透明。 |

## 动作行

前 9 行（Row 0 ～ Row 8）对应桌面宠物的 9 类标准状态。每行从第 0 列向右依次排列：

| 行号 | 状态键名 | 帧数 | 空置格 | 画面动作与情绪表现 |
| ---: | --- | ---: | ---: | --- |
| **0** | `idle` | 6 | `(0,6)..(0,7)` | **待机与眨眼**：双手放在展开的电脑旁安静呼吸，第 2～4 帧完成半闭眼、闭眼再睁开的眨眼循环。 |
| **1** | `running-right` | 8 | 无 | **抱电脑向右走**：合上笔记本抱在胸前，迈开 8 帧完整步态循环向右行进。 |
| **2** | `running-left` | 8 | 无 | **抱电脑向左走**：独立绘制的向左行进 8 帧步态（非镜像翻转，严格保留右侧蓝发夹与左侧呆毛）。 |
| **3** | `waving` | 4 | `(3,4)..(3,7)` | **坐姿挥手**：坐姿状态下抬起一只戴深色手套的手左右轻摆打招呼。 |
| **4** | `jumping` | 5 | `(4,5)..(4,7)` | **坐姿小跳**：抱着展开的电脑向上轻跃（最高抬升 21 px），第 4 帧稳稳落回与 `idle` 完全重合的坐姿基线。 |
| **5** | `failed` | 8 | 无 | **求助与平复**：任务出错时眉头微蹙、眼含委屈向上求助，随后深呼吸平复回坐姿。 |
| **6** | `waiting` | 6 | `(6,6)..(6,7)` | **等待回复**：停下敲击，头部微倾向上看，等待你的下一步指令。 |
| **7** | `running` | 6 | `(7,6)..(7,7)` | **专注敲代码**：表示 Agent 正在执行任务（注意与左右移动的 `running-right`/`left` 区分），双手在键盘上忙碌敲击。 |
| **8** | `review` | 6 | `(8,6)..(8,7)` | **检查结果**：身体微倾凑近屏幕，认真审视代码改动或输出日志。 |

## 播放时长

- **运行时调度权归属应用**：在 Codex 中，当前播放哪一行、每帧停留多少毫秒均由客户端内部调度器决定，`pet.json` 与仓库内的 `art/animation-layout.json` 不会覆盖应用的调度策略。
- **预览动图采样时长**：
  - `idle` 待机预览采用 `[1680, 660, 660, 840, 840, 1920]` ms（完整呼吸+眨眼周期共 `6.6 秒`），复刻自桌面端构建 `26.1007.71326` 中实测的播放节奏。
  - `look-loop.gif` 转头预览将每个方向设为 `200 ms`，仅用于顺时针连续展示全部 16 个方向；在真实 Dot 中由鼠标方位实时决定显示哪一格。

## 导出与归一化铁律

在将高分辨率单帧拼合为 `1536 × 2288` 最终整图时，需遵循以下五条规则（其中第 1–2 条为制图与拼图阶段的归一化规范，第 3–5 条的成品约束由 `scripts/validate.py` 与 `scripts/audit_artwork.py` 自动核查，预览动图由 `scripts/render_previews.py` 派生）：

```text
❌ 错误做法：按每帧各自的可见像素边界（Bounding Box）单独撑满格子
   ┌──────────────┐    ┌──────────────┐
   │  ╭────────╮  │    │ ╭──────────╮ │  ← 当角色抬手或歪头时，独立缩放会导致
   │  │ 头变大 │  │ vs │ │ 身体忽缩 │ │    身体和电脑在播放时忽大忽小（呼吸感变抽搐）
   └──┴────────┴──┘    └─┴──────────┴─┘

✅ 正确做法：全套帧共用同一个虚拟相机取景框与统一缩放比（Shared Viewport）
   ┌──────────────┐    ┌──────────────┐
   │    ╭────╮    │    │   ╭────╮     │  ← 笔记本底座与双脚锚定在同一水平线上，
   │   ┌┴────┴┐   │ vs │  ┌┴────┴┐    │    四周留出 >= 1 px 透明安全边距，绝不裁边
   └───┴──────┴───┘    └──┴──────┴────┘
```

1. **统一取景与缩放比**：所有采用帧必须使用同一个虚拟相机窗口和缩放比例放入 `192 × 208` 格子，严禁按单张图自己的不透明边界单独拉满。
2. **保留干净的原生透明度与描线色彩**：当生成图的透明边缘已经干净时，直接保留原始 RGBA，**不要用“把半透明边缘与邻近浅色填色做平均”的后处理脚本**（详见 [v1.0.1 头发描线修复记录](OUTLINE-REPAIR.zh-CN.md) 的经验教训）。
3. **四周保留至少 1 px 透明安全边距**：每个有效格的非零 Alpha 边界框必须满足 `x0 >= 1, y0 >= 1, x1 <= 191, y1 <= 207`，防止纹理采样时在格子边缘产生截断伪影。
4. **空白格零脏点**：15 个未使用的格子必须保持完全透明（不得残留任何 `alpha > 0` 的杂点），且第 9、10 行共 16 个转头姿态必须完整填满。
5. **无损编码与单源派生**：导出无损 WebP 后，必须校验 `spritesheet.webp` 与 `art/final/spritesheet.png` 解码后的 RGBA 字节 100% 相等，再从这份最终 WebP 派生出 `art/frames/` 下的 73 张裁剪帧和 `previews/` 下的所有预览图。
