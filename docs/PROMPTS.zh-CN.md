# 提示词与多模态制图手册

[English](PROMPTS.md) · **简体中文** · [文档目录](README.zh-CN.md)

在制作 73 格有效画面的 Codex v2 桌宠精灵整图（`1536 × 2288`，8 列 × 11 行）时，最常见的翻车原因不是模型不会画画，而是**提示词一次要求太多、缺少视觉锚点，或者把有缺陷的过渡帧当成下一轮底图继续传声筒式放大误差**。

这份手册整理了菲比啾比从建立角色母本、扩展单帧动作、修复局部穿帮、重绘 Dot 16 向转头，到执行无标签双盲方向审查的 7 套核心提示词模板。每套模板不仅给出可直接复用的文本，还说明了**为什么要附上特定参考图**以及**每一条约束真正在防止什么错误**。

---

## 0. 提示词工作的黄金准则

```text
+-------------------------------------------------------------------------+
|  1. 每次只生成 / 修改一帧（禁止让模型一次画完一整条多格精灵图带）          |
|  2. 永远以“已定稿姿势母本”作为第一锚点，相邻帧只用来控制动作步幅          |
|  3. 明确区分“允许动的部分”与“必须锁死原位的部分（机位/电脑/双脚/躯干）”   |
|  4. 遇到脸部变形或比例膨胀时，丢弃坏帧，退回最近的好帧重新单步插值         |
+-------------------------------------------------------------------------+
```

在使用以下模板前，请务必先把对应的参考图附进对话上下文，并将方括号 `[...]` 替换为当前目标状态、帧序号或具体缺陷。

## 1. 建立角色姿势母本（Character Anchor）

在动手画任何一格动画之前，必须先从社区三视图出发，锁定**坐姿使用展开的电脑**与**怀抱合上的电脑行走**两张姿势母本。这两张图将决定全套 73 个有效格的头身比、帽檐宽度、配饰左右归属与笔记本透视。

### 提示词模板

```text
根据附上的正面、侧面、背面参考，绘制一只透明背景的菲比啾比。
保留紧凑的 Q 版比例、浅金长发、宽白帽与深紫帽带、分层紫色眼睛、
白色服装、深色手套、条纹腿部和深色鞋。

蓝色发夹保持在观看者右侧，呆毛和蓝布在左侧。
使用深色外轮廓和金棕色内部发丝线。

姿势：[坐着使用一台打开的蓝灰色电脑／抱着同一台合上的电脑]。
电脑只有一层屏盖、一处铰链和一套键盘，双手位置清楚合理。
完整保留帽子、头发、双手和双脚，并留出边距。
一只角色，透明背景，不要文字和标签。
```

### 为什么这么写？

- **“蓝色发夹保持在观看者右侧，呆毛和蓝布在左侧”**：用**观看者视角（viewer-left / viewer-right）**代替“角色左右侧”，防止模型在左右镜像理解上混淆。
- **“电脑只有一层屏盖、一处铰链和一套键盘”**：图像生成模型画打开的笔记本时极易多画一层悬浮屏幕或把键盘画在屏盖背面；显式写死物理结构能大幅降低废片率。
- **“使用深色外轮廓和金棕色内部发丝线”**：缩到 **192 × 208** 原生单格尺寸后，浅金色头发如果缺乏深色外轮廓会直接融进亮色桌面背景，而内部发丝如果也是纯黑又会显得脏乱。

## 2. 编辑单张动作帧（Edit One Animation Frame）

当姿势母本通过检查后，前 9 行的 57 张标准动作帧都围绕母本做单步偏移。每次生成时附上**姿势母本** + **一张已认可的相邻帧**。

### 提示词模板

```text
把附图角色修改成一张动作帧。
状态：[waiting]。位置：[第 2／6 帧]。变化：[轻微歪头，期待回复]。

保留角色身份、头身比例、帽子大小、长发轮廓、紫色眼睛结构、线宽、
服装、配饰方向和电脑结构。
相机、坐姿身体、双脚和电脑位置保持稳定。
相邻帧只用于判断动作幅度，不用来重新定义角色造型。
只修改预定的头部、表情或手部动作，背景透明，输出一张独立帧。
```

### 动作扩展要点

- **移动行（`running-right` / `running-left`）**：在提示词中写明屏幕行进方向、支撑腿和步态阶段（迈步、跨中、收步），左右两侧分别独立绘制，严禁水平镜像翻转整张图。
- **坐姿小跳（`jumping`）**：明确写清起跳、最高点、下降或落地缓冲阶段，继续使用展开的电脑和统一缩放基准，确保 `idle → jumping → idle` 起落 0 px 落地偏移。

## 3. 修复局部问题（Repair a Defect）

当某帧的表情和动态已经非常传神，但局部出现了多一只手套、袖口断开或屏幕多了一条接缝时，不要重抽整张图，而是附上对应部位的基准图做靶向外科修复。

### 提示词模板

```text
修复[电脑右侧重复的手套]。
依据角色基准，恢复为[一只与白色袖子连接的手]。
保留已有表情、轮廓、比例、配饰和所有不受影响的特征。
继续保持一台电脑和透明背景。
```

> **经验提示**：局部修复完成后，务必重新检查完整轮廓，并把修好的图放回相邻帧序列中按 **192 × 208** 原生尺寸连播，确认修补区域没有引入线宽跳变或边缘杂色。

## 4. 绘制 Dot 转头姿态（Create a Dot Look Pose）

第 9、10 两行共 16 格用于 Codex Dot 的鼠标视线跟随，方向使用屏幕极坐标（完整 16 个角度定义见[格式说明](FORMAT.zh-CN.md#转头方向)）。这一步最容易犯的错是让模型理解成“角色全身旋转”，导致电脑跟着转走。

<p align="center">
  <img src="../art/repair/v1.0.2/review-boards/before-after-cardinals.png" width="760" alt="四正方向修复前后对比" />
</p>

### 提示词模板

```text
绘制 [090] 方向：角色应当明确看向[屏幕右侧]。
角度从屏幕正上方顺时针增加：000 上、090 右、180 下、270 左。

用头部朝向、眼神、脸部形状和帽顶可见面积表达方向。
保持已有紫色眼睛的画法和配饰方向。
身体、电脑、双脚、相机、缩放和地面接触点保持稳定。
只输出一张透明背景帧，坐姿身体不随头部一起转向。
```

### 绘制顺序建议

1. **先完成四个正方向**：先锁定 `000`（正上）、`090`（正右）、`180`（正下）、`270`（正左），确保俯仰时帽顶可见面积与脸颊透视合理，左右转头时视线明确分开。
2. **再补中间姿态**：每新增一张 `22.5°` 过渡姿态，都同时对比前后两个相邻方向，确保视线角度单调递进。

## 5. 修复脸部大小跳变（Repair a Face-Size Jump）

在 v1.0.2 修复转头环路时，我们遇到了一个典型问题：从左上区（`292.5° → 315° → 337.5° → 000°`）转回正上方的几格里，电脑底座明明没动，但菲比啾比的脸却像突然凑近镜头一样放大了一圈，或者脸颊显得被捏窄。

这是因为如果拿一张已经有轻微变形的帧再去生成下一帧，模型会把变形带进下一次生成。正确做法是**选择两张比例正确的相邻姿态作为锚点，在它们之间直接生成一张完整透明背景角色帧**（失败帧仅用于对照，绝不单独抠脸缩放粘贴）：

### 提示词模板

```text
在提供的两张已认可姿态之间，生成一张完整透明背景帧。
第一张图是身体、电脑、镜头和角色大小的精确基准。
让头、脸、刘海和附着的配饰一起小幅转动。
保持原眼睛画法、脸颊比例、眼距和短下巴。
透视逐渐靠近第二张姿态。

身体、双手、电脑、坐姿腿部和双脚保持原位，沿用现有帽子造型。
不单独缩放头部、不贴脸、不增加眼睛图案，不改变镜头，
也不按每张角色自己的轮廓单独撑满画布。
只输出一张完整、连接正确的角色帧。
```

### 为什么严禁“单独缩放头部或贴脸”？

- 菲比啾比的宽檐白帽、金发刘海、右侧蓝发夹与脸颊之间有紧密的透视遮挡关系。局部贴脸或液化会破坏刘海落点与帽檐弧度，在 **192 × 208** 原生尺寸下立刻暴露出拼贴感。
- 坚持输出完整连接的角色帧，并在原生尺寸下对比前后两帧与 `idle`，留意电脑不动时脸是否仍然像突然放大。

## 6. 审查单帧与完整动作（Review Frames and Motion）

图片生成完毕并切入网格后，提供**角色基准 + 相邻帧 + 原生尺寸静帧 + 实际循环动图**，使用以下模板做全面体检：

### 提示词模板

```text
对照基准图审查提供的帧和动画。
检查角色一致性、头身比、配饰方向、双手、面部线条、电脑结构、
轮廓颜色、透明度和位置对齐。

查看九类动作、十六方向循环，以及待机 → 小跳 → 待机的衔接。
检查首尾接续、表情变化、角色大小、道具连续性和落地位置。

每项结论给出“通过／需留意／不通过”，注明对应帧或过渡、
可见依据和具体修改方向。区分有意的眨眼姿态与画面错误。
不要推断所提供媒体中没有展示的动作。
```

根据审查结果定位修复，再重做受影响的对比；文件结构与像素校验由 `scripts/validate.py` 另行完成。

## 7. 无标签方向审查（Blind Direction Review）

如果把印着 `270.png` 的图片连带文件名发给模型问“她往哪看”，模型往往会顺着文件名猜出答案。

为了测出真实的画面朝向可读性，必须隐去文件名、方向标签和答案表，把 14 组水平/垂直对称方向打乱成无标签 `A / B` 配对图，先收集独立判断再揭晓答案（汇总与通过标准见[方向审查](REVIEW.zh-CN.md#方向审查)）：

<p align="center">
  <img src="../art/repair/v1.0.2/review-boards/blind-axis-pairs.png" width="720" alt="无标签 A/B 对称轴盲测图板" />
</p>

### 提示词模板

```text
逐组判断无标签 A/B 图片的视线方向。
用屏幕坐标分别描述两张图：左／右，或上／下。
给出把握程度和可见依据。不确定时直接说明。
只依据所提供的图片，不查看答案表。
```

保留所有分歧点并回到 16 向顺序转头循环中核查，确保每一格既能在单张盲测中分清左右上下，也能在连续转头时自然衔接。
